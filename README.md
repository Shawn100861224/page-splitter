# 图片自动分区 · 按题目切段

把一张拍照/截图丢进浏览器，自动识别文字区块按题目切开，拖一拖分界线改成你要的样子，一键导出 ZIP。

**在线使用：** https://shawn100861224.github.io/page-splitter/

## 特点

- **图片不上传。** 纯前端，零后端，没有账号、没有统计、没有网络请求 —— 断网也能用。
- **自动分区。** 二维背景归一化 → 行墨迹剖面 → 间距聚类，能扛住光照不均、页面阴影、底部桌面。
- **一定要能手改。** 分界线可拖动、可添加、可删除、可用方向键微调，改错了 `Ctrl+Z` / 撤销按钮回退。
- **干不了的页面会先说。** 双栏、整页粘连（反光/太暗）会直接在状态栏下面给出提示，而不是默默切错。
- **手机上直接进相册。** 点「保存到相册」走系统分享面板（iOS 选「存储 N 项」→ 照片；Android 分享面板里的相册/照片）。浏览器不支持时自动退到大图面板，长按图片即可「存储到照片」，每张也有独立下载按钮。
- **横向不截字。** 分析窗只取"够密的那一段"来算行剖面，但导出/缩略图按**真实墨迹列范围**裁（判据：该列墨点 ≥ 带高 1.2% 的行数），窗外的字不会被切掉；桌面、阴影列因为局部对比被归一化掉，不会把黑边带进来。
- **首页讲清楚能干什么、不能干什么。** 三步用法 + 适合/不适合两栏，不用先传一张图才知道它是干嘛的。
- **手机返回键不会直接退出网站。** 进了编辑器按返回 = 回到选图页；开着「保存图片」面板按返回 = 关面板，还在编辑器；只有在选图页按返回才离开。
- **零依赖。** 没有框架、没有构建步骤；ZIP 打包是自己写的 ~90 行 store 模式实现（导出的都是 JPEG，再压也不省空间）。

## 加一个回归样本（参数要调通用就靠这个）

```bash
# 原图放进 samples/（已在 .gitignore，不会上传），一条命令生成夹具 + 真值 + 索引
python tools/make_fixtures.py samples/*.jpg
python tools/make_fixtures.py samples/印刷试卷.jpg --kind print --note "横排单栏印刷"      # 分类打标
python tools/make_fixtures.py samples/密排讲义.jpg --kind print --baseline               # 切得不对的样本只锁基线
npm test          # 每个 case 都会跑：JS 必须逐带逐段复现 Python
```

夹具 = 缩小灰度（gzip）+ 缩略 PNG + `*.truth.json`（Python 的 bands/regions）+ `cases.json` 索引。
**真值来自 Python 实现，是"当前行为的基线"，不等于"正确答案"**：样本本身切得不对时用 `--baseline` 标记，
测试只保证"两边一致、结果没漂"，不假装它切对了。

## 命令行用法（不想要网页时）

```bash
python tools/split_blocks.py page.jpg --dry-run          # 只打印分析结果
python tools/split_blocks.py page.jpg --out crops --write  # 落盘 part-01.jpg ...
python tools/split_blocks.py page.jpg --gap-ratio 0.40 --write   # 切得少一点
```

需要 `Pillow` + `numpy`。

## 参数是怎么定的

全部按比例（相对纸面亮度、带高、页宽），不写死像素，所以换分辨率不用重新标定：

| 参数 | 默认 | 作用 |
|---|---|---|
| `bgDiv` | 16 | 背景估计的降采样倍数；越小越贴局部阴影，越大越稳 |
| `inkRatio` | 0.55 | 灰度 < 该值 × 局部背景 → 算墨 |
| `smoothRatio` | 0.004 | 行剖面平滑窗（占页高比例） |
| `rowThreshRatio` | 0.012 | 行算墨的行门槛（占页宽比例） |
| `minBandRatio` | 0.006 | 带高下限（占页高比例） |
| `smallBandRatio` | 0.5 | 小于「中位带高 × 该值」的碎带并到更近的一侧 |
| `gapRatio` | 0.36 | 间距 > 该值 × 中位带高 → 切开（网页上的「灵敏度」滑块） |

### 阈值不只看比例，还看"这页有没有两档间距"

印刷页的行距是一档、题间是一档，而且是**跳跃式**的（实测 20px → 158px）；手写页的题间距只比行距高一点点（51px → 55px），没有跳跃。所以在排序后的间距里找最大跳跃 `g[i+1]/g[i]`：≥ 2.2 倍、且上面还有 ≥ 2 个间距，就认定存在两档，阈值取跳跃中点；否则退回 `gapRatio × 中位带高`。

这条规则是必须的：只有比例阈值时，印刷题册会被按行切成 15 段（实际 5 道题）。

### 样本与实测结果

| 样本 | 类型 | 带 | 段 | 说明 |
|---|---|---|---|---|
| `handwritten-ruled` | 手写横线本（真实照片） | 14 | **8** | 人工逐题核对过；侧光阴影 + 底部桌面 |
| `exam-print` | 印刷题册（合成） | 15 | **5** | 两档跳跃生效前是 15 段 |
| `screenshot` | 截图式白底（合成） | 9 | **3** | 同上，生效前 9 段 |
| `two-column` | 双栏（合成） | 18 | 1 | 只出警告，不分段 |
| `dense-print` | 印刷密排（合成） | 1 | 1 | 整页粘连，提示重拍 |

合成样本只代表几何排版，不代表真实纸张/光照，所以标了 `--baseline`：它们锁的是"别退化"，不是"切得对"。

## 已知限制（别指望它全自动）

- **竖排 / 双栏 / 表格** 不支持，横排单栏才是它的场景；双栏会被检测出来并提示（中间整列空白），但不会自动分栏切。
- **手写很淡** 时会漏带（漏了就手动加一条分界线）。
- **相邻题挨得太近**（间距落在阈值 ±30% 内）自动切不一定对，页面会提示，需要你核对。
- 不识别题号，也不知道「这一题从哪开始」—— 它只认"墨迹成组 + 间距"。所以题号断行（如一个大括号单独一行）可能被并到上一题。
- **行距和题间距差不多的页面仍然会切错**：几何上就是分不开，只能靠"两档跳跃"这个线索。行距乱、题间也没明显留白的页，请当它是"粗分割"起手，再手改。
- 大图分析前会缩到长边 4096 且总像素 ≤ 2500 万（48MP 原图直接分析会在 iPhone 上把页面撑爆），导出仍按原图分辨率裁剪。
